# 踩坑清单（每一条都真实发生过）

> 按"杀伤力"排序。前 5 条是**必须遵守**的，后面是"知道了能省几小时"的。

---

## 🔴 一级（会导致任务失败 / 数据丢失）

### 1. 微信失去前台 → 所有点击静默失效

**现象**：截图正常、点击返回 `dispatched: true`、但什么都不发生。

**原因**：坐标点击是 CGEvent 投递到前台应用的，微信不是前台时事件被丢弃；原生库有时会抛 `FOREGROUND_REQUIRED`，有时**静默忽略**。

**对策**：
- 每次动作前 `activate()` 并等 **1.3 秒**（0.25s 不够）
- 动作间隙不要离开去操作别的窗口
- 批量任务前明确告知用户：这段时间不要动电脑

---

### 2. 误点窗口右上角的控件 → 窗口与主界面合并、标签全丢

**现象**：点错标签栏最右侧的图标（搜索/合并/通知），微信窗口立刻合并到主窗口，所有已打开的文章标签消失。

**对策**：
- 标签栏右侧 `x > 窗口宽度 86%` 的区域**视为禁区**
- 所有点击前先用 OCR 确认目标文本，不要盲点坐标
- 一旦发生：只能从公众号主页重新打开列表（之前采集的进度务必已落盘）

---

### 3. 误点「关闭全部标签页」

**现象**：`···` 菜单最后一项是「关闭全部标签页 `⌘W`」，误点后所有标签关闭，连列表页也没了。

**对策**：
- 菜单项**按 y 坐标选定行号**，只点「复制链接」那一行（第 3 行，y≈128/1028）
- 绝不按「最后一行」这种相对位置点

---

### 4. `⌘W` / `Ctrl+Tab` / `⌘Shift+]` 在微信里禁止使用

**现象**：`⌘W` 关的是**整个窗口**而不是当前标签，直接触发窗口合并。

**对策**：关标签只能用 UI 交互（悬停标签最左端 → 出现 ✕ → 点 ✕）。

---

### 5. 残留的弹出菜单会吞掉滚轮事件

**现象**：滚轮完全无效，页面纹丝不动，持续 20 分钟找不到原因。

**原因**：之前某次点击打开了 `···` 菜单，菜单一直开着，滚轮事件被菜单吃掉。

**对策**：**每次动作前先按 `Esc`**（无菜单时按 Esc 无害）。

---

## 🟠 二级（会浪费大量时间 / 产生错误数据）

### 6. 标签压缩后「···」消失，出现"只有一个标签"的错觉

**现象**：标签超过 ~4 个后会被压缩成窄标签，只显示图标；GUI Agent 常以为标签不存在。

**对策**：**悬停**目标标签（哪怕看起来只有图标）→ 等 450ms → 该标签会展开并显示 `✕ / ⟳ / ···` → 再 OCR 定位。

---

### 7. 视觉 Agent 的截图会撑爆上下文

**现象**：每步截图约 2000 token，几百步后上下文溢出，任务被迫中断。

**对策**：**绕开框架的 screenshot 工具**，直连 CUA 原生 socket 取图落盘，用 Python 离线分析（本项目 `scripts/cua_socket_client.mjs`）。

---

### 8. 图片区域点击可能不触发跳转

**现象**：点文章卡片的封面图没反应，点标题却可以。

**原因**：封面图可能只是 `<img>`，标题才是 `<a>`。

**对策**：统一**点标题文字**（OCR 定位标题行，点其左侧 20px 处）。

---

### 9. 滚动到底部不会自动加载，需要等待

**现象**：列表到底后滚轮无反应，以为没有更多文章。

**对策**：滚动无变化时**等待 3–5 秒**，页面会自动加载下一批；连续 3 次无变化才判定到底。

---

### 10. OCR 会把图标读成数字

**现象**：
```
🎧 71人  → "671人"   （耳机图标读成 6）
👍 3     → 单字符识别失败
在看=0   → 显示「写留言」文字，不是数字
```

**对策**：见 `docs/03-architecture.md` 的"结构化裁剪 + 部件分类"方案。

---

### 11. 数字粘连：3 个指标被读成 1 个

**现象**：`凸37 A 115 34016` —— 实际是 `赞37 / 转发115 / 在看34 / 评论16`，但最后的 `34` 和 `016` 粘在一起。

**对策**：不要按"字符个数"猜，要按**连通域间距**分组；间距 >26px 就是新组。

---

### 12. 站点文本框是受控组件，程序化 paste 不生效

**现象**：文本出现在框里，但点「批量下载」没反应（框架 state 仍为空）。

**对策**：优先用站点**自己的「快速粘贴」按钮**（它走剪贴板 API）；或先点击已有文本行让输入框真正获得焦点，再全选粘贴。

---

## 🟡 三级（细节，但影响体感）

### 13. 批量下载按钮位置随输入框高度变化

文本框内容越多，按钮越往下。必须**每批重新 OCR 定位按钮**，不能写死坐标。

### 14. 站点限流返回「服务器繁忙」

并发 2 → 偶发限流；改成 **单线程 + 每篇间隔 2.5 秒** 后 0 失败。

### 15. 文件名与标题不一致

下载站用标题命名但**去掉标点**（`创业公司董事会：到底几个人好？` → `创业公司董事会到底几个人好.md`）。
→ 匹配时统一做 `NFKC + 去非字母数字中文 + 小写` 归一化。

### 16. 跨年度的老文章可能没有评论图标

2015–2016 年的文章微信未开评论，底部栏只有 `👍 ↗ ♡` 三个图标 → 评论数记 0。

### 17. 公众号列表页会把日期当成卡片标题

OCR 把「10月31日」这类日期行识别成标题 → 需要过滤 `^\d+月\d+日$` 模式。

### 18. 窗口几何会突变（`WINDOW_CHANGED`）

窗口被移动/缩放/切换 Space 时原生库拒绝操作。
→ 捕获该错误，**重新连接**（相当于重新读取窗口几何）再重试，别硬重试同一次调用。

### 19. 同一篇文章会重复打开

标题 OCR 每次略有差异 → 精确去重失效 → 同一篇反复打开。
→ 去重键用**归一化标题前 4 字**（或 `publish`），别用完整标题。

### 20. 关闭标签时可能关错（关掉列表页）

悬停标签左端后，✕ 出现在**该标签最左侧**；如果 OCR 框包含多个标签，会算错位置。
→ 优先关**最右侧**的文章标签（从右往左关），并在点击后校验"标签数减少"。

---

## 一句话总结

> **所有 GUI 自动化事故，本质都是"没确认状态就发下一次动作"。**
> 每次动作前：确认前台、确认窗口几何、确认目标文本、清掉残留弹层。
> 每次动作后：读一次状态，别假设成功。
