# 子任务：截图解析（交给独立 subagent）

```
# 任务
从 /data/shots/*.png 的微信文章底部操作栏截图里，解析出四个数字：
赞（likes）/ 转发（shares）/ 在看（wows）/ 评论（comments）。

# 输入
每张图是文章页底部条带，形如：[头像] 公众号名  👍 13  ↗ 5  ♡ 2  💬 9

# 已知难点（必须处理，否则准确率不到 50%）
1. 图标会被 OCR 读成数字：🎧 71人 → "671人"
2. 单字符细体数字 OCR 经常失败
3. 指标为 0 时，微信显示「写留言」文字而非数字
4. 三个数字可能粘连：凸37 A 115 34016

# 正确做法（传统 CV，CPU 即可，不用 GPU）
1. 灰度 + 二值化（阈值 140）
2. 8 邻接连通域（行游程 + 并查集）得到每个字形 bbox
3. 字形过滤：14 ≤ h ≤ 60
4. 4 个图标用模板匹配识别（图标在 UI 里像素级一致）：
   - 从任意一张图裁出 4 个图标，归一化 32×32 作为模板
   - 对候选图标尺寸（28≤h≤48, w≥22）的连通域做最近邻
5. 每个图标**右侧、间距 ≤26px** 的连续连通域 = 该指标的数字
   - 宽 ≤22 → 数字；宽 >22 → 文字（如「写留言」→ 该指标 = 0）
6. 数字识别不要用 OCR：
   - 把已确认的数字字形归一化 20×20
   - 用多位数整体 OCR 成功的结果自动打标（逐位切分）
   - 建 0–9 模板库 → 最近邻分类
7. 没有数字的图标 → 0

# 验收标准
- 必须在至少 20 张图上肉眼核对（用 read_image 看图对比）
- 准确率 ≥95% 才能交付
- 输出 JSON：{"2026-04-16_11-05": [赞, 转发, 在看, 评论], ...}
- 失败/不确定的留 null，不要猜
```

---

## 经验：给子 agent 的输入要给足

- 明确**数据在哪**（路径 + 命名规则）
- 明确**输出格式**（JSON schema + 保存路径）
- 明确**验收方式**（人工看图 + 抽样数 + 准确率门槛）
- 明确**边界**（拿不准的留 null，宁缺毋滥）
